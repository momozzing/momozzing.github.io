[Claude 편](https://momozzing.github.io/study/Claude-Memory-Analysis/)과 [ChatGPT 편](https://momozzing.github.io/study/ChatGPT-Memory-Analysis/)에서 따로 정리한 두 서비스의 메모리를 나란히 놓는다.
각 항목의 출처와 세부 내용은 앞 두 글에 있고, 여기서는 차이와 그 차이가 어디서 오는지만 본다. 조사 시점은 2026년 10월 8일이다.

출처 수준 표시는 앞 글과 같다. [공식]은 회사 문서, [역분석]은 외부 사용자의 2025년 관찰이라 현재와 다를 수 있다. 표시 없는 건 내 계정 화면에서 확인한 것이다.

## **1. 한눈에 비교**

| | Claude (claude.ai) | ChatGPT |
|---|---|---|
| 기억 단위 | 카테고리별 개별 항목 (Profile·주제·영역) | 백그라운드에서 합성한 메모리 상태, 사용자에겐 소제목별 서술형 요약. 개별 항목(저장된 메모리)은 legacy로 공존 |
| 쓰는 시점 | 대화 중 바로 작성·갱신 (2026-07~) | 백그라운드 프로세스(Dreaming)가 여러 대화를 함께 읽고 통합 (V0 2025-04, V3 2026-06) |
| 매 대화 주입 | 기억 항목 | 합성된 메모리 상태 |
| 과거 대화 원문 | 필요할 때 채팅 검색 tool로 꺼냄 (RAG) | 합성 입력으로 쓰고, 개별 대화는 출처(Sources)로 표시. 요청 시 세부 정보 검색 |
| 사용자가 보는 화면 | Topics 목록, 항목별 날짜, 읽기·수정·삭제 | 메모리 요약(수정, 다시 언급하지 않기), 응답 아래 출처, 저장된 메모리 목록(버전 기록) |
| 시간 처리 | 공개 자료 없음 | 시간이 지나면 고쳐 씀 ("갈 예정" → "다녀옴") |
| 프로젝트 | 프로젝트마다 별도 메모리, 선택지 없음 | 기본 메모리 / 프로젝트 전용 선택, 공유 프로젝트는 전용 고정 |
| 민감정보 | 건강·신념은 옵트인, 신분증·범죄·금융은 저장 안 함 | 공유하면 나타날 수 있다고 안내, 규제 워크스페이스는 기본 꺼짐 |
| 기억 안 남기기 | Incognito (읽기·쓰기 모두 안 함) | 임시 채팅 (읽기 선택, 쓰기 안 함), 빠른 답변, Health 분리 |
| 삭제 | 항목 개별 삭제, 대화 삭제 ≠ 기억 삭제 | 위치마다 따로 삭제, 채팅 기록 참조 끄면 30일 내 삭제, 삭제 로그 최대 30일 |

## **2. 같은 뼈대**

차이부터 보기 전에 같은 데를 짚어 둔다. 둘 다 이렇게 생겼다.

- 짧은 사용자 기억은 매 대화에 넣는다
- 원문 대화는 그대로 두고 따로 다룬다
- 대화를 지워도 기억은 남고, 기억은 따로 지운다
- 프로젝트 안의 기억은 밖과 분리할 수 있다
- 기억을 만들지 않는 대화 모드가 있다

[논문 21편 회고](https://momozzing.github.io/study/Agent-Memory-Retrospective/)에서 제일 여러 번 나온 결론이 "원본을 남긴 쪽이 나았다"였다.
두 서비스 모두 원문 대화를 버리지 않는다. 기억은 그 위에 얹은 요약이나 추출물이고, 틀리면 원문에서 다시 만들 수 있다.
이건 이미 합의된 부분으로 보고, 아래는 그 위에서 갈린 선택을 본다.

## **3. 갈린 선택**

### **3.1 기억을 만드는 시점**

Claude는 대화 중에 쓴다. ChatGPT는 대화가 끝난 뒤 백그라운드에서 쓴다.

둘은 서로 반대 방향으로 이동했다.

| | 이전 | 현재 |
|---|---|---|
| Claude | 하루 단위 합성 요약 (2025-09) | 대화 중 항목 갱신 (2026-07) |
| ChatGPT | 대화 중 `bio` tool 저장 (2024-04) | 백그라운드 합성 Dreaming (2025-04 V0, 2026-06 V3) |

각 방식이 잘하는 게 다르다.

대화 중 쓰기는 반영이 빠르다. 방금 말한 게 다음 대화에 바로 있다. 대신 보는 범위가 그 대화 하나다. 여러 대화에 걸친 모순을 정리하거나, 시간이 지나서 바뀐 사실을 고쳐 쓰는 일은 그 대화 안에서 할 수 없다.

백그라운드 합성은 여러 대화를 한 번에 본다. 모순을 정리하고 "예정"을 "다녀옴"으로 바꿀 수 있다. 대신 반영까지 시간이 걸리고, 사용자가 어느 대화에서 뭐가 들어왔는지 추적하기 어렵다.

ChatGPT 내부 평가에서 2024(대화 중 저장) → 2026(Dreaming V3) 사이에 가장 많이 오른 축이 "시간이 지나도 최신 유지"(9.4% → 75.1%)였다. 사실 회상(41.5% → 82.8%)보다 폭이 크다. OpenAI가 백그라운드 합성으로 간 이유는 이 축이라고 봐도 될 것 같다.

Claude는 시간 처리에 대한 공개 자료가 없다. 대화 중 갱신 구조에서 "예정"이 지난 뒤 어떻게 되는지 모른다.

-> 둘 다 겪어보고 반대로 간 거라서 어느 쪽이 맞다고 말하기 어렵다. Claude는 합성 요약의 느린 반영과 불투명함을 버렸고, ChatGPT는 개별 저장의 낡음과 모순을 버렸다.

### **3.2 기억 단위와 사용자 가시성**

Claude는 항목이고 ChatGPT는 문단이다.

Claude Settings > Memory에는 항목마다 제목, 한 줄 설명, 업데이트 날짜가 붙는다. 영역 하나를 열면 수천 자 문서다.
ChatGPT 메모리 요약은 소제목 6개 아래 "당신은 …"으로 시작하는 서술형 문단이다. 문단 안의 개별 문장에는 날짜나 출처가 없다. 제목 옆에 전체 갱신 시각 하나만 있다.

이 차이는 3.1에서 바로 따라온다. 대화 중에 하나씩 쓰면 항목이 되고, 여러 대화를 합성하면 문단이 된다.

가시성 면에서 Claude가 단순하다. 뭘 언제 알았는지 목록 하나에서 보인다.
ChatGPT는 그 빈자리를 출처(Sources)로 메운다. 메모리 요약은 "무엇을 알고 있나"를, 응답 아래 출처는 "이번 답에 무엇을 썼나"를 보여준다. 둘을 합쳐야 Claude 목록 하나와 비슷한 투명성이 나온다.

대신 ChatGPT에는 Claude에 없는 게 있다. 저장된 메모리의 버전 기록과 복원(2025-10), 출처를 관련 있음/없음으로 표시하는 피드백(2026-05), 요약에 "다시 언급하지 않기"(2026-06). 갱신과 적용 양쪽에 사용자가 끼어들 수 있다.

### **3.3 과거 대화 원문에 접근하는 길**

Claude는 검색 tool이다. [역분석, 2025-12] 기준으로 `conversation_search`(키워드)와 `recent_chats`(최근순) 둘이고, 과거 맥락을 미리 요약해서 넣지 않고 필요할 때만 호출한다.

ChatGPT는 원문을 두 가지로 쓴다. Dreaming이 읽는 합성 입력이 하나, 요청 시 과거 채팅에서 세부 정보를 찾는 경로(2026-01-15)가 둘이다. 후자는 Claude의 채팅 검색과 같은 역할인데 tool 이름이나 호출 방식은 공개되지 않았다.

-> 겉으로는 다른데 2026년 들어 가까워졌다. Claude는 원래 검색만 있었고, ChatGPT는 합성 위에 검색 경로를 추가했다. 회고에서 "저장보다 검색이 자주 막힌다"고 정리했는데, 두 회사 다 검색 쪽에 손을 대고 있다. ChatGPT는 2026-05-05에 과거 대화 검색 속도도 따로 개선했다.

### **3.4 프로젝트 격리**

Claude는 격리가 기본이고 선택지가 없다. 프로젝트 안의 맥락은 전역 메모리나 다른 프로젝트로 섞이지 않는다.

ChatGPT는 프로젝트마다 기본 메모리 / 프로젝트 전용 중 고른다. 기본 메모리를 고르면 프로젝트 밖 채팅도 참조하고 밖에서도 이 프로젝트를 참조한다. 공유 프로젝트만 전용으로 고정한다. 대신 프로젝트 메모리 목록은 볼 수 없다.

Claude 쪽이 단순하고 ChatGPT 쪽이 유연하다. 유연한 만큼 규칙표가 3행 4열이 됐고, Enterprise·Edu는 또 다르다.

### **3.5 삭제의 의미**

둘 다 대화 삭제와 기억 삭제가 분리돼 있다. 대화를 지워도 거기서 만들어진 기억은 남는다.

차이는 지울 데의 개수다. Claude는 항목을 지우면 끝이다. ChatGPT는 메모리 요약, 저장된 메모리, 채팅, 파일, 연결된 앱 다섯 군데를 따로 지워야 하고, 채팅 기록 참조를 끄면 30일 안에 삭제되며, 삭제된 메모리 로그는 최대 30일 보관될 수 있다.

ChatGPT 개인화 출처가 다섯 가지인 데서 오는 비용이다. 넣는 데가 많으면 지울 데도 많다.

### **3.6 민감정보**

Claude는 [공식, 2026-08-25] 건강, 신념 같은 민감 주제를 기본으로 저장하지 않고, 설정을 켜야 저장한다. 신분증 번호, 범죄 기록, 금융 계좌 번호는 요청해도 저장하지 않는다.

ChatGPT 도움말은 "민감한 정보를 공유하면 메모리에 나타날 수 있다"고 안내한다. 사용자 쪽 옵트인 설정은 도움말에 없다. 대신 조직 단위로 다룬다. 의료 서비스용과 규제 대상 Enterprise는 향상된 메모리가 기본 꺼짐이고, Health 대화는 나머지와 분리 보관한다.

[역분석] 2025년 `bio` tool 규칙에는 민감 범주(인종·종교·정밀 위치·건강·정치 성향)를 저장하지 않는다는 항목이 있었다. 모델 쪽 규칙으로는 걸렀을 가능성이 있는데, 사용자가 켜고 끄는 설정으로는 노출되지 않았다.

Claude는 사용자 설정으로, ChatGPT는 워크스페이스 정책과 모델 규칙으로 푼다.

### **3.7 기억을 남기지 않는 모드**

Claude Incognito는 기억을 읽지도 쓰지도 않고 채팅 기록에도 남지 않는다.
ChatGPT 임시 채팅은 쓰기만 막는다. 기존 메모리를 읽을지는 시작할 때 고른다.

ChatGPT에는 메모리를 안 쓰는 경로가 더 있다. 빠른 답변(2026-04)은 일반 정보 질문에 메모리를 참조하지 않고, Health(2026-01)는 메모리를 아예 분리 보관한다.

## **4. 논문 결론과 맞춰보기**

[회고](https://momozzing.github.io/study/Agent-Memory-Retrospective/)에서 여러 논문에 겹친 결론이 넷이었다. 두 서비스가 거기에 어떻게 서 있는지 본다.

### **4.1 원본을 남긴 쪽이 나았다**

둘 다 남긴다. 2절에서 봤다.

다만 메모리 자체의 성격은 다르다. Claude 항목은 추출형에 가깝고, ChatGPT 요약은 합성형이다.
[Memory Portability](https://momozzing.github.io/paper%20review/Memory-Portability-Paper-review/)는 요약형 메모리가 모델을 바꾸면 흔들리고, 원본이 없으면 복구가 안 된다고 했다. ChatGPT는 요약형이지만 원문 대화를 두고 다시 합성하는 구조라 복구 조건은 갖췄다. Dreaming V3 발표에 "기존 저장된 메모리로 되돌리기 가능"이 들어 있다.

### **4.2 저장보다 검색이 자주 막힌다**

Claude는 처음부터 검색 tool 중심이다. ChatGPT는 2026년에 검색 경로(1월)와 검색 속도(5월)를 추가했다.
두 회사 모두 검색에 투자하고 있는데, 검색이 키워드인지 벡터인지, 몇 개를 가져오는지는 양쪽 다 공개하지 않았다.

### **4.3 모델을 올려서는 안 풀린다**

여기 해당하는 공개 자료는 양쪽 다 없다. 두 회사 모두 메모리 구조 변경을 모델 변경과 별도로 발표했다는 점 정도가 간접 증거다. Claude 2026-07 구조 변경, ChatGPT 2026-06 Dreaming V3 모두 모델 출시와 묶이지 않았다.

### **4.4 대화 전체를 넣은 점수와 먼저 비교한다**

둘 다 없다. ChatGPT는 내부 평가 세 축을 공개했지만 full-context 기준선은 없다. Claude는 평가 수치 자체가 없다.

그 밖에 논문에서 봤던 것들을 두 서비스에 대보면 이렇다.

| 논문에서 본 것 | Claude | ChatGPT |
|---|---|---|
| 갱신 전 옛 버전과 비교 ([Janus](https://momozzing.github.io/paper%20review/Janus-Selective-Memory-Update-Paper-review/)) | 공개 자료 없음 | 저장된 메모리 버전 기록·복원 (사용자 수동) |
| 시간 정보 처리 ([Zep](https://momozzing.github.io/paper%20review/Zep-Paper-review/)) | 공개 자료 없음 | 문장을 고쳐 씀, 평가 축으로 세움 |
| 무엇을 저장할지 선별 ([What Deserves Memory](https://momozzing.github.io/paper%20review/NEMORI-Paper-review/)) | [역분석] 적용 시 선택적 사용 규칙 | [역분석] `bio` 저장 규칙, 자동 우선순위 관리 |
| 원문 위 검색 ([ReFind](https://momozzing.github.io/paper%20review/ReFind-Paper-review/)) | 검색 tool 2개 | 요청 시 세부 정보 검색 경로 |
| 메모리 안 지시 무시 (프롬프트 인젝션) | [역분석] 명시 규칙 있음 | 공개 자료 없음 |

## **5. 설계에 가져갈 것**

두 서비스를 보고 나서 메모리를 만든다면 가져갈 것과 피할 것이 정리됐다.

가져갈 것은 이렇다.

1. 원문 대화는 그대로 두고, 기억은 그 위에 얹는다. 둘 다 그렇게 한다.
2. 기억 항목마다 날짜를 붙인다. Claude 화면에서 제일 유용했던 부분이다.
